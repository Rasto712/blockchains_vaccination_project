# Report outline - Developer 5

This is a checklist, not a completed assessed report. Check coursebook length/structure and Week 6 presentation rules before writing.

1. Problem and short cited research on current healthcare/data-sharing systems: what works and what limits user control.
2. Roles and requirements: guardian, child subject, trusted clinic, school, doctor and deployer.
3. Architecture and data mapping: local identity/vaccination attributes versus on-chain hashes, grants, events and reward balances.
4. Contract design: registration, exact scopes, 1-365 day duration, revocation, persistent denied audit and reward restrictions.
5. Implementation: actual completed modules, versions and compile/deploy/test/run instructions.
6. Validation: observed unit/integration results and why each tested function matters.
7. Evaluation: actual deployment/per-function gas plus small-user-count timing tables with sample counts and limitations.
8. Demonstration and limits: role selection is local demo mode; Python mediates disclosure; hashes do not prove physical delivery or clinical completeness.

Do not copy placeholder tests or blank CSVs into the report as successful outcomes. Optional frontend/public testnet work comes only after mandatory features pass.
